### DSH 卡死与代理路径

启动故障包含 resolve hook 重入、宿主 schema API 兼容和目录读取无法及时结束等问题。目录错误不能让整个模型选择器一直等待；超时后保留 fallback 或已知目录，并明确记录来源，不能把 fallback 当成 VM 目录读取成功。

DSH `0.2.1-rc.5` 的 `dsh-experimental-inspector` 会用 `new Request(input, init)` 包装全局 `fetch`，再只把 `Request` 交给原 `fetch`。Node 的扩展参数 `dispatcher` 因此丢失，可能出现启动目录预热走代理、随后推理改为直连的情况。插件现在使用自身 `undici.fetch` 与 `ProxyAgent`，不依赖宿主全局 `fetch` 包装器保留该参数。

该判断已有不联网的真实观察器函数 replay。原 Inspector 选定文件的 REA Evidence 为 `ev_000df5d6eb1b671da931d59f15bcd502611a43a7a982085fa66373951f635f87`，覆盖范围仅为选定文件。绕过观察器的 gateway 请求以插件目录日志和 VM 请求日志核对，不能再依赖该观察器显示完整网络情况。

## Cloudflare / WARP 决策

本轮保持现有 HTTPS 入口，不接入 CF、不安装 WARP。先让源站具备大请求、解压、内存准入、并发、超时和可观测能力，再用实际负载判断是否需要更换入口。

CF 的边缘网络和平台限制不能替代源站保护。即使边缘接收上传，VM 仍需读取、解压和解析请求；压缩后的较小传输体也可能对应很大的解压体。多个请求同时进入时，源站仍可能因 body 缓冲、字符串或 JSON 对象副本超出内存。源站必须自行限制这些资源。

入口链路与 VM 到上游的出口链路分别测量。WARP 的出口路由变化不会自动解决本机到入口的上传瓶颈，也不能用一次较快请求证明持续收益。VM 上游代理的连接状态和节点健康同样不能从网关总处理时间直接推断。

若后续测试 CF，应保留现入口并增加测试入口，使用上述 20MB、30MB、50MB 负载比较上传耗时、首 token、P95 和完整流成功率，覆盖晚高峰。WARP 的出口测试另行进行，避免同时修改入口和出口后无法判断收益。当前尚未执行这些 CF / WARP 对照测试。

CF 官方限制也会进入链路预算：普通代理 Free / Pro 的入站 body 上限为 100MB，但回源 Proxy Read Timeout 为 125s、Proxy Write Timeout 为 30s，不能将后者误当客户端上传总时限。Workers 每 isolate 只有 128MB 内存，直接把大 JSON 整体解析搬到 Worker 仍会触发内存问题。当前网关采用更长的上游 / SSE 预算，接入 CF 前还需验证长时间无数据的响应、上传与取消行为。

资料（2026-11-01 查询）：[CF 连接限制](https://developers.cloudflare.com/fundamentals/reference/connection-limits/)、[上传限制](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/4xx-client-error/error-413/)、[Workers 内存](https://developers.cloudflare.com/workers/platform/limits/)、[Caddy streaming](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#streaming)。Caddy 的负 `flush_interval` 会使客户端断开后后端请求继续；SSE content-type 已自动即时 flush，本轮移除该设置并验证取消传播。

公网首次连接曾在 TLS 握手前出现一次 ECONNRESET；重复的 chunked 上传又发生 EPIPE，Caddy 在收到 557,049 bytes 后记录 unexpected EOF / 502。VM 无重启或 OOM，未进入上游推理，资源随后归零。另一次 Node 探针完整接收 20MiB（40.28s）、gzip 30MiB 和 zstd 50MiB；curl 固定长度 20MiB / 512KiB每秒上传也通过（客户端40.39s、Caddy39.46s）。这些是小样本，尚不能把现有本机到VM链路判为长期稳定，也不能定位到具体订阅节点。首次短请求探针使用 input 字符串简写被上游 400 拒绝，改为 DSH 实际使用的消息数组及 instructions 后返回 200；这不是大 body 请求推理通过的证据。真实大输入受模型上下文限制，当前大请求 hash / 内存验收使用模拟上游，真实模型仅验收短输入。

当前决定：保留本轮完成的 Node 网关和现有入口，不改写成 Worker，不安装 WARP。基于公网瞬断证据，CF 的稳定测试入口值得后续做 A/B；这不等于已证实 CF 能加速。CF 与 WARP 分开测，长期成功率 / P95 / 晚高峰未验收。

## SIWC 重新授权（`login.mjs --reauth`）

对照官方 token-sharing 文档的 self-hosted VM 流程，原 `scripts/login.mjs` 有两个缺口：注册模式固定以 `dynamic_agent_client` 发起、并要求回调携带 `client_id`，因此同一账号再次授权会得到**新** `client_id` 和新注册，而不是文档要求的 reauthorization（复用已签发 `client_id`、携带同一 `ext_agent_host_id`、以 retained `id_token` 作 `id_token_hint`、可选 `login_hint`、省略 `agent_name_hint`；回调**可能不带** `client_id`）。另外原脚本只读 `storeDir/host_id` 而从不写入，重新登录会生成新的 host ID。

本轮改动：

- 新增 `--reauth` 与 `--client-id <id>`。`--reauth` 按 `savedAt` 选择存储中的注册（或按 `--client-id` 精确选择），没有注册时退出码 1 并提示先注册。
